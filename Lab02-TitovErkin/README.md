ПР2. Ответы на контрольные вопросы

### 1. Почему для хранения денег используют decimal, а не double? Что может пойти не так с double?
Тип `double` хранит числа в двоичной системе с плавающей точкой (стандарт IEEE 754), из-за чего большинство привычных десятичных дробей (например, `0.1` или `0.2`) не могут быть представлены абсолютно точно. В результате вычислений накапливается погрешность (например, `0.1 + 0.2` дает `0.30000000000000004`), что недопустимо в финансовых расчетах, где важна точность до копейки. Тип `decimal` основан на десятичной системе счисления с высокой точностью (28–29 значащих цифр) и исключает подобные погрешности округления.

### 2. Что произойдёт, если целочисленный тип (например, byte) переполнится, то есть значение выйдет за границы диапазона?
По умолчанию в C# (в непроверяемом контексте `unchecked`) при переполнении происходит перенос/циклическое «оборачивание» (overflow wrap-around). Например, для типа `byte` с диапазоном от `0` до `255`, прибавление `1` к `255` приведет к значению `0`. Если бы код выполнялся внутри блока `checked`, программа выбросила бы исключение `OverflowException`.

### 3. Чем var отличается от динамической типизации в Python? В какой момент компилятор определяет тип переменной, объявленной через var?
В C# `var` — это статическая неявная типизация: тип определяется компилятором ровно один раз **во время компиляции** на основе выражения в правой части. После этого переменная жестко закрепляет свой тип, и присвоить ей значение другого типа нельзя (будет ошибка сборки). В Python же используется динамическая типизация: тип связывается не с переменной, а с объектом во время выполнения (runtime), поэтому переменной можно в любой момент присвоить значение другого типа (например, сначала число, потом строку).

### 4. Какой тип данных всегда возвращает Console.ReadLine(), независимо от того, что ввёл пользователь?
Метод `Console.ReadLine()` всегда возвращает строку — тип `string` (или `null`, если достигнут конец потока).

### 5. Чем int.Parse отличается от int.TryParse в поведении при некорректном вводе (например, буквы вместо цифр)?
При некорректной строке `int.Parse` выбрасывает исключение `FormatException`, из-за чего программа аварийно завершает работу, если ошибка не перехвачена через `try-catch`. В свою очередь, `int.TryParse` не выбрасывает исключений: он просто возвращает логическое значение `false`, обеспечивая безопасную работу.

### 6. Что означает false, возвращённый из int.TryParse, и что при этом попадёт в переменную, переданную через out?
Значение `false` означает, что строку не удалось преобразовать в целое число (введены буквы, спецсимволы, пустая строка или число за границами типа `int`). В переменную, переданную через параметр `out`, при этом записывается значение по умолчанию для целевого типа (для `int` это `0`).

### 7. Приведите пример, когда стоит использовать TryParse, а не Parse — и объясните, почему.
**Пример:** Любой ввод данных пользователем через консоль или веб-форму (например, запрос возраста, баланса, количества товаров). 
**Почему:** Разработчик никогда не может гарантировать, что пользователь введет корректные цифры, а не опечатается (введет «двадцать», нажмет Enter на пустой строке или поставит случайную букву). Использование `TryParse` позволяет избежать аварийного падения приложения, корректно обработать ошибку через `if (!success)` и запросить ввод повторно. `Parse` допустим только тогда, когда строка поступает из строго контролируемого и уже валидированного источника.
